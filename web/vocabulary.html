    How this is built

    1. Sample. Ten five-minute windows a day, one from each 2.4 hour block, start times drawn from the date so a run can be repeated. About a thousand public pull request descriptions a day.
    2. Split off the signature. Tools sign their work, either as a trailing line that reads like attribution or as a shouted HTML comment. That block is cut from the text before a word is counted, so nothing here can learn the signature itself.
    3. Label. The signature alone decides whether the writing goes in the signed group or the unsigned one. Which tools exist is the only part kept up to date by hand, through a pull request, because it is the only part that goes stale on its own.
    4. Count, then discard. Each day becomes one small file of word counts and the text is thrown away. Counts are kept per day, so any window can be rebuilt later and a word's history stays readable.
    5. Divide. A word's score is its rate in signed descriptions over its rate in unsigned ones. Both groups come from the same days, so anything driven by the calendar (a new tool everyone starts naming, say) cancels out, and what is left is the writing.

    The unsigned group is not a human control. Plenty of machine-written descriptions carry no signature, which makes the two groups more alike, so every number here is a floor and not a ceiling. The corpus is pull request prose and carries that shape.

    Rebuilt daily by GitHub Actions. The counts behind this page are in data/counts, one file a day. The idea of measuring pull request prose this way, and the first twenty months of samples, come from louisabraham/load-bearing, which reaches the same vocabulary by clustering instead of by reading the signatures.
