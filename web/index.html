prosecheck

A linter for prose.

Flags stock LLM phrasing — it is important to note that, no X, no Y, no Z — at the line it came from, with the fix. Nothing leaves your browser.

    Open this page from a link#gz=…

    Everything is in the fragment, which browsers never send to a server. --share writes the link and gzips the file into it.

    #gz= #text=       the document, base64url
#url=              fetch a page and lint it
#kind=             md · html · txt
#rules=            a rule set URL, repeatable
#select= #ignore=  set names or rule ids
#mode=fudge        test rules instead

    Same keys work on check.html — the same checker with no interface, for when you want the result and not the page. It renders plain text or #format=json, sets <html data-status="done">, exposes window.slopResult, and postMessages the findings to a parent frame, so a headless browser or an embedding page can read it without installing anything.

    slop check --share --share-base …/web/check.html --share-format json doc.md
    Writing and testing rulesthe fudger

    A rule set is JSON. Each rule carries its own examples, and those examples are what makes it testable.

    { "id": "utilise", "kind": "regex",
  "pattern": "\\butili[sz]e[sd]?\\b", "flags": "gi",
  "suggest": "Write \"use\".",
  "tests": { "hit": ["We utilise the cache."],
             "miss": ["The utility ran overnight."] } }

    Test rules above — slop fudge mine.json — checks every example, then rewrites each one 27 ways with the markup real files carry and requires the rule to still fire:

    **It is important to note that** this works.   md:bold-span
It is imp**ort**ant to note that this works.   md:bold-inside-word
It is important\nto note that this works.      md:soft-wrap
<p>It is imp<b>ort</b>ant to note that …       html:tag-inside-word
<p>It is important <!-- note --> to note …     html:comment-before-word

    A variant that turns a hit into a miss is a bug — in extraction, or in a rule too tight for real files. Its first run found four, including soft-wrapping silently breaking every multi-sentence rule on 80-column markdown.

    Install as an agent skillSKILL.md

    The repo ships a SKILL.md so a coding agent picks this up on its own when it is editing prose, without being told to run anything. Copy it into your skills directory:

    D=~/.claude/skills/linting-prose        # or .claude/skills/… for one project
R=https://raw.githubusercontent.com/bheijden/slop/main/skill

mkdir -p $D/reference
curl -sL $R/SKILL.md -o $D/SKILL.md
for f in rules authoring; do curl -sL $R/reference/$f.md -o $D/reference/$f.md; done

    Or hand the instruction to the agent and let it install itself:

    Install the slop skill from
github.com/bheijden/slop/tree/main/skill into
~/.claude/skills/linting-prose/, keeping the reference/ files.
Then lint docs/ and fix what it reports.

    Only the name and description sit in context until the skill is triggered, so it costs about 100 tokens to have installed. The body loads when the agent is actually editing prose, and reference/rules.md and reference/authoring.md only when it needs the rule catalogue or is writing a rule.

    A skill gives an agent instructions it will act on, so read one before installing it — this one runs npx against this repo and nothing else. See Anthropic's Agent Skills docs.

    Markup is stripped before the rules run and every offset maps back, so a finding points at the line in your file. Source and rule format · Apache-2.0 · patterns from Simon Willison's LLM cliché highlighter and Wikipedia's Signs of AI writing.
